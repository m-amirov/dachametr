Изолированный визуальный срез на базе PR #11. Он не подключается к рабочему Vite UI и не меняет `src/domain` или `src/ui`.

## Screens and states

- `index.html` — desktop workspace 1440×900: structure / editor / BOM;
- clicking `Дорожка` and then `Песок карьерный` opens the selected-material inspector;
- at 390×844 and 768×900 `Зоны`, `Редактор` and `Ведомость` are separate tabs; selecting a zone returns to the editor and persists through the BOM tab;
- `?state=error` shows a fail-closed BOM state;
- `design-board.html` — tokens, typography, grid and component states;
- `side-by-side.html` — actual PR #11 / PR #12 baseline against the new composition;
- `reference-audit.md` — six official Rayon references with adopted and rejected moves.
- `visual-audit.md` — independent composition and geometry audit with explicit PASS / NOT RUN / BLOCKED boundaries.

## Data provenance

`scenario.json` is generated by `scripts/generate-workspace-scenario.mjs`, which imports `src/domain/plot.ts` and stores its SHA-256. Derived numbers are not handwritten in the UI. The current scenario is:

- 20×30 m plot → 600 м²;
- 2×4 м bed → 8 м², soil 25 cm;
- 2×5 м path → 10 м², sand 10 cm + gravel 5 cm;
- engine-derived BOM: 3 600 л with reserve, 72 packages, 2 345 kg where density is provided.

## Evidence boundary

Evidence under `evidence/latest/` records exact source SHA, Chromium, DPR, viewport, scrollWidth/clientWidth, console/request errors, PNG SHA-256 and `getBoundingClientRect()` geometry checks for both zones at 320, 390, 768, 1024 and 1440 px. `BLOCKED / NOT RUN`: physical mobile device, real soft keyboard, assistive technology, production font rendering and working-app integration. OpenDesign Cloud generation is `NOT RUN`.
