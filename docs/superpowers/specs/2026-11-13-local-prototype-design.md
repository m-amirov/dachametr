# Дачаметр — дизайн локального прототипа

Статус: рабочее решение для ограниченного Prototype Gate, 13.11.2026.

## Цель и границы

Сделать локальный инструмент, в котором пользователь проходит один полный путь: размеры участка → зоны → слои материалов → точная ведомость закупки. Интерфейс должен объяснять единицы и округление, не скрывать ошибки и не создавать впечатление географической схемы участка.

Вне scope остаются публикация, SEO-страницы, аккаунты, сервер, цены, сохранение после reload, URL-share, координаты зон, карта, нормы и значения плотности по умолчанию.

## Направления

### A — «Измерительный инструмент» — выбранное рабочее направление

Светлая бумажно-графитовая поверхность, тонкая линейная сетка, крупные числовые значения и компактные рабочие панели. Участок и зоны образуют основную последовательность ввода, ведомость закреплена рядом на широком экране и идёт сразу после форм на узком. Предметные элементы — шкала единиц, строка площади и таблица закупки; карта или декоративные иллюстрации не используются.

### B — «Планировщик зон» — отклонено для v0

Больше визуальных блоков зон и условных мини-схем. Направление хорошо для будущих координат, но в текущей модели координат нет; схема легко создаст ложное обещание размещения.

### C — «Материальная ведомость» — отклонено для v0

Таблица и закупочные итоги доминируют над вводом. Это удобно после заполнения, но ухудшает первый сценарий и мобильное редактирование, где пользователь сначала создаёт зоны и слои.

## Визуальные токены A

- Поверхность: `#f5f2ea`; основной текст: `#19342e`; вторичный текст: `#5e6c67`.
- Граница: `#cfd6cf`; мягкая панель: `#e7eee8`; акцент действия: `#b95436`; итог: `#245c4a`; ошибка: `#a43b34`.
- Типографика: системный sans-serif с кириллицей для форм и таблиц; serif-заголовки только для коротких названий инструмента. Внешние шрифты и сетевые ассеты не загружаются.
- Геометрия: радиус 10–14 px только у рабочих поверхностей; поля и строки остаются прямыми и плотными. Без градиентов, декоративных иконок, рекламных карточек и hero-блока.
- Состояния: видимый `:focus-visible`, текстовая ошибка рядом с полем, `aria-live` для общего статуса и результата, disabled только для действий, которые действительно недоступны.

## Архитектура

Vite собирает статическую страницу, а UI написан на TypeScript без React и без UI-библиотеки. `src/domain/*` остаётся независимым от DOM. `src/ui/model.ts` хранит draft-строки и стабильные ID, `src/ui/validation.ts` преобразует draft в доменную модель и связывает ошибки с полями, `src/ui/app.ts` отвечает за DOM-рендер и делегирование событий, `src/styles.css` — за responsive presentation. Домен получает только валидные значения; промежуточные `1,` и `-` остаются в draft.

Для зональной расшифровки будет добавлен детальный доменный API, использующий те же точные промежуточные значения, что и существующий `calculatePlot`; публичный результат существующего метода и golden fixtures не изменяются.

## Проверяемые состояния

Initial без зон, valid участок, добавление и удаление зон, слой с новым материалом, повторное использование материала, `1,` в редактируемом поле, invalid input с сохранением ввода, fail-closed BOM, упакованный материал, россыпь, плотность и две массы, warning при суммарной площади зон больше участка, grouped BOM и зональная расшифровка.

Сохранение между перезагрузками не обещается: приложение явно сообщает, что данные живут только в текущей сессии.
