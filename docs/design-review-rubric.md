# Визуальная рубрика «Дачаметра» — проверка готового рендера

Не оценивать «красоту» по исходникам и Figma-макету. Вход: фактическая страница, браузер/commit, снимки 320/390/768/1440 px и состояния initial/editing/error/result. Физическое устройство отдельно от эмуляции. Документ дополняет docs/design-principles.md.

| Критерий | Что проверить | Критический дефект |
| --- | --- | --- |
| Task-first | Видны цель, ключевые поля и способ получить результат без скролла через рекламу | Калькулятор спрятан за декоративным hero |
| Точность языка | Русские метки, понятные единицы, ясный результат, натуральная точность | Итог без единиц или ввод обманчив |
| Система | Последовательность typography, colors, spacing, actionable focus/error | Состояния визуально неразличимы |
| Индивидуальность | Диаграммы объясняют площадь, полив, слои; композиция предметная | Безосновательный копипаст типового SaaS-шаблона |
| Мобильная версия | 320/390 px, 200% zoom, длинные подписи, tap targets | Границы обрезают поле или результат |
| Доступность | Контраст, tab order, live errors, aria/labels по назначению | Управление невозможно с клавиатуры |
| Спокойствие | Анимация только по действию, нет фейковых отзывов, random gradients, лишних бейджей | Маркетинговый шум мешает расчёту |

## Протокол
На каждый P0/P1 записать URL/commit, браузер, viewport/DPR, screenshot-path, reproduction, expected-vs-observed, severity, решение. Не «улучшать» стиль по абстрактному вкусу без связи с заданием пользователя.
Результат: PASS при наличии визуальных доказательств и отсутствии блокирующих дефектов; FAIL при наблюдённом блокере; BLOCKED при невозможности захватить текущий рендер. Автоматизированная accessibility-проверка не заменяет ручной keyboard-проход.
