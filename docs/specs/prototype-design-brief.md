# Эскиз интерфейса и дизайн-бриф первого локального прототипа

**Статус:** исследовательское предложение, без реализации и согласованной палитры. Ссылается на `plot-zones-materials-v0.md`. Цель — дать отдельному Codex design review достаточно предметного контекста без готового шаблонного SaaS UI.

## Сценарий пользователя
«У меня участок 20×30 м; я хочу понять, сколько грунта нужно для двух грядок, а сколько песка и щебня — для основания дорожки; хочу видеть литры, кубометры и мешки там, где сам указал объём мешка».

### Компоненты первого экрана
- **Верх:** название инструмента, короткое честное назначение, никаких длинных hero, ложных оценок и рекламных блоков.
- **Панель участка:** размеры с единицами, м² и сотки; предупредить, что форма прямоугольная и не заменяет межевание.
- **Редактор зон:** небольшие понятные карточки/строки с названием зоны, размерами и добавлением материалов; нет фальшивой карты и автоматического размещения прямоугольников.
- **Результаты по слоям и общий BOM:** видны рядом при desktop и ниже на узком экране; не прятать формулы. При ошибке в одной зоне остальные данные сохраняются и ошибочный расчёт не смешивается с валидным.
- **Мобильная версия:** явный порядок «участок → зоны → результат», без sticky панели, закрывающей поля, экранную клавиатуру или итог.

## Три направления для будущей дизайн-проверки (не выбранные)
- **А — Измерительный инструмент:** компактные формы, табличный BOM, умеренная линейная геометрия, типографика для чисел.
- **Б — Планировщик зон:** спокойные логические блоки с доминирующими понятными зонами и миниатюрными условными схемами, не изображающими GPS.
- **В — Материальная ведомость:** сильная итоговая таблица, единицы и прозрачный вывод расчёта, приоритет закупки без магазина.

Дизайнер после отдельного разрешения должен представить 2–3 визуально разные концепции (фон, шрифт с кириллицей, таблица результатов, responsive) **без изменения существующих утверждённых цветов** и без скачивания сторонних skills. Поскольку утверждённой палитры пока нет, нельзя выдавать какой-либо вариант за принятое решение.

## Независимая визуальная приёмка после реализации
Screenshots/проходы: initial, два слоя, неверный ввод, отредактированная зона, пустой список, сгруппированная упаковка; 320/390/768/1024/1440, ru-RU запятая, zoom, keyboard, touch, display font/asset decode. До запуска приложения визуальный PASS невозможен.
